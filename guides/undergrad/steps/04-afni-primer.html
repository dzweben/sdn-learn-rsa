AFNI Primer

Learn the essential AFNI concepts, file types, and commands used in this project.

Key AFNI Ideas

Datasets

AFNI uses paired HEAD/BRIK files or NIfTI (.nii.gz). The HEAD file contains metadata (grid dimensions, labels). The BRIK file contains the actual voxel data.

Sub-bricks

Multi-volume datasets contain many sub-bricks. Our stats files have ~130 sub-bricks: beta coefficients (Coef), t-statistics (Tstat), and F-statistics (Fstat) for each of the 41 conditions.

Commands

Most work is done via command line with reproducible scripts. Commands start with 3d (e.g., 3dinfo, 3dROIstats).

Commands Used in This Project

CommandStageWhat It Does
afni_proc.py 3 Generates the preprocessing + GLM script from a template
3dDeconvolve 3 Runs the GLM to estimate beta coefficients for each condition
3dROIstats 4 Extracts mean values from ROI masks — gives one scalar per condition per ROI
3dmaskdump 5 Dumps every voxel value within a mask — gives a full pattern vector per condition per ROI (for RSA)
1dtranspose 5 Transposes a .1D matrix (rows ↔ columns). Used to flip voxels×conditions into conditions×voxels
3dresample 4 Resamples a mask to match the GLM grid (required when mask and data have different voxel grids)
3dUndump 4b Creates an ROI mask from coordinates (used to build the dmPFC sphere)
3dinfo Any Shows metadata: grid dimensions, voxel size, space, sub-brick labels
3dCM 4 Reports center of mass of a mask (for verifying ROI placement)

Basic Commands (Preview)

Try these AFNI commands on real data
3dinfo -n4 -ad3 -space stats.958+tlrc

Shows grid dimensions, voxel sizes, and coordinate space.

3dinfo -label stats.958+tlrc | tr '|' '\n' | head -10

Shows the first 10 sub-brick labels (e.g., Full_Fstat, FBM.Mean60.r1#0_Coef).

3dROIstats -nzmean -quiet -mask VMPFC-mask-final.nii.gz "stats.958+tlrc[1]"

Extracts the NZmean beta for sub-brick 1 (FBM.Mean60.r1) from the vmPFC mask. This is exactly what the extraction scripts do for all 41 conditions.

3dCM VMPFC-mask-final.nii.gz

Reports the center of mass of the vmPFC mask in DICOM coordinates.

3dmaskdump -mask dACC1_glmgrid+tlrc "stats.958+tlrc[1]" | head -3

Dumps voxel values from sub-brick 1 within dACC1 (46 voxels). Each line = i j k value. This is how Stage 5 extracts full patterns.

3dinfo -n4 dACC1_glmgrid+tlrc

Verify the resampled mask matches the GLM grid (64 76 64 1).

Key Concept: NZmean Extraction (Stage 4)

The ROI extraction scripts use 3dROIstats -nzmean to compute the non-zero mean within each mask. This ignores voxels with value 0 in the mask, so only the ROI region contributes to the average.

The command outputs two columns per line: Mean and NZMean. Our scripts extract only the NZMean (last column) using awk '{print $NF}'.

Result: one scalar per condition per ROI — good for behavioral correlations, but not for RSA.

Key Concept: Voxel Pattern Extraction (Stage 5)

RSA compares multi-voxel patterns, not single means. Stage 5 uses 3dmaskdump to extract every voxel's beta value within the ROI mask for each condition.

The workflow is:

  1. 3dresample — resample the mask to match the GLM grid (required because 3dmaskdump does not auto-resample like 3dROIstats)
  2. 3dmaskdump — dump all voxel values within the mask for all 41 condition sub-bricks
  3. 1dtranspose — flip from [voxels × conditions] to [conditions × voxels]

Result: a matrix of shape (41 conditions × N voxels) per subject per ROI. This is what RSA operates on — you compute 1 − Pearson r between condition rows to build a neural RDM.
